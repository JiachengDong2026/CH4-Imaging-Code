# CH569 USB3.0 Minimal Loopback Firmware

The first hardware checkpoint deliberately uses the vendor-provided 200T
loopback firmware unchanged. It transfers one fixed 4096-byte USB bulk OUT
block to FPGA over 32-bit HSPI, then returns the same block through USB bulk
IN. Keeping this known-good firmware makes the FPGA and board bring-up
independent of the later application protocol.

The board USB connector is owned by the CH569 MCU. The FPGA bitstream alone
cannot enumerate a USB device.

The vendor-built HEX used by this checkpoint is copied to:

```text
Firmware/CH569/HSPI_USB_Loopback.hex
```

The original source project supplied with the board is:

```text
E:\Work\甲烷巡检系统\盘A_ACX750-CH569 USB3.0开发板标准配套资料\02 设计实例\USB3.0例程\200t\ch2_ACX750_CH569_200T_USB30_LoopBack.rar
```

Build/program `HSPI_USB_Loopback` with MounRiver Studio, or program the copied
HEX with WCHISPTool. The USB firmware waits for the FPGA-ready input on CH569
PA12 before it calls `USB30D_init(ENABLE)`. On this board PA12 is connected to
FPGA `Bitstream_Done` at C19.

For the vendor `ch2` loopback image, install all three control jumpers:

| FPGA GPIO0 pin | FPGA net | U29 pin | CH569 net | Purpose |
|---|---|---:|---|---|
| C19 | `Bitstream_Done` | 5 | `SCS1#` / PA12 | FPGA-ready input |
| E19 | `Rx_Ctrl` | 6 | `MOSI1` / PA14 | FPGA receive enable |
| D19 | `Tx_Ctrl` | 8 | `MISO1` / PA15 | FPGA transmit enable |

The tutorial's single `GPIO1 -> U29-8` jumper belongs to the speed-test
example, where C19 is used as `Tx_En`; it is not the complete wiring for this
loopback image. U29 pin numbering is the physical header numbering shown in
the schematic, not the CH569 GPIO number.

The copied vendor HEX is the unmodified file from the board support package.
SHA-256: `2C4E2F9BD65A1FDD94D3CC04A87FA8480275D402E7D3BCA1EB6C354A4C2DAFF0`.

Required programming order:

1. Program the FPGA loopback image.
2. Ensure C19/`Bitstream_Done` is high; the loopback image drives it high after
   the 50 MHz MMCM locks.
3. Program the CH569 loopback firmware if it is missing or was overwritten.
4. Power-cycle the board or short-press `USB_RST` so the CH569 reruns startup.

The FPGA image for the same checkpoint is generated by:

```powershell
& 'D:\Software\Vivado\Vivado\2020.2\bin\vivado.bat' -mode batch -source FPGA/scripts/build_usb3_loopback.tcl
```

Program `FPGA/build/usb3_loopback/ch4_usb3_loopback.bit` or the vendor image
with `FPGA/scripts/program_vendor_usb3_loopback.tcl`. Then use the
`USB3.0Demo.exe` included in the same archive to send and verify a 4096-byte
block. `Bitstream_Done` is connected to the CH569 FPGA-ready input expected by
that firmware.

The vendor source waits at the following startup gate until C19 is high:

```c
while(!GPIOA_ReadPortPin(GPIO_Pin_12));
mDelaymS(100);
while(!GPIOA_ReadPortPin(GPIO_Pin_12));
HSPI_Init();
USB30D_init(ENABLE);
```

This fixed-block firmware is only the electrical/link validation target. The
next checkpoint will replace its blocking loop with ping-pong buffers and pass
the existing CH4 application byte stream without changing the application
frame format.

## Stage 2 unidirectional stream firmware

The first stage-2 firmware is kept separately in `usb3_stream/Main.c`. It no
longer waits for USB EP2 data. Instead, it receives one 4096-byte FPGA HSPI
packet, checks the CH569 hardware CRC/sequence status, and publishes a valid
packet through USB EP1. Failed HSPI packets are discarded rather than exposed
to the host.

Build output:

```text
Firmware/CH569/CH569_USB3_Stream.hex
SHA-256: D23AB869250F8C3F1ECEA4A5CA40B7AF134BF88D2E45D75A06DEBB51F6CE876F
```

This image is not compatible with the loopback FPGA image because that image
requires a completed FPGA receive transaction before it transmits. Program it
only together with the forthcoming FPGA stream-test bitstream.
